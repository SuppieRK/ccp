## Purpose
Define the streaming semantic engine contract for event processing, context-keyed dedupe, masking safety, audit metadata, and validation gates.

## Requirements

### Requirement: Unified Event-Driven Filtering
The engine SHALL process output through a single tool-filter contract over line, EOF, and tick events.

#### Scenario: Line event handling
- **WHEN** a wrapped command emits a line in filtered mode
- **THEN** the engine forwards a line event to the active filter and applies the returned action.

#### Scenario: EOF handling
- **WHEN** a stream reaches EOF for a context
- **THEN** the engine forwards EOF and flushes buffered output when the filter returns flush semantics.

#### Scenario: Tick handling
- **WHEN** the runner emits stale ticks at `250ms` intervals
- **THEN** the engine forwards tick events and emits flush output only when filters request it.

### Requirement: Exit-Aware Write-Path Compaction
Write-path compaction SHALL be driven by explicit command-exit outcome events.

#### Scenario: exit event delivery
- **WHEN** a wrapped command exits
- **THEN** the engine receives an explicit exit event with exit metadata (including exit code).

#### Scenario: successful write-path compaction
- **WHEN** a write-path filter receives a success exit outcome
- **THEN** it MAY emit compact success summaries according to command-specific policy.

#### Scenario: failed write-path diagnostics preservation
- **WHEN** a write-path filter receives a non-zero exit outcome
- **THEN** success-only compact formatting is not applied
- **AND** failure diagnostics are preserved without destructive compaction.

#### Scenario: missing exit outcome safety
- **WHEN** a write-path filter has not received an explicit exit outcome
- **THEN** it MUST default to safe behavior and MUST NOT assume success.

### Requirement: Context-Keyed Ordered Dedupe
The engine SHALL maintain ordered dedupe buffers keyed by filter-selected context keys.

#### Scenario: Default context isolation
- **WHEN** default filters are used
- **THEN** context keys isolate by command id, tool, and stream.

#### Scenario: Shared-context opt-in
- **WHEN** a filter returns a shared context key across streams
- **THEN** stdout/stderr lines participate in one shared dedupe buffer.

#### Scenario: Context cleanup after complete EOF
- **WHEN** all seen streams for a context have received EOF and flush completed
- **THEN** the engine removes that context from memory.

### Requirement: Deterministic Flush Ordering
The engine SHALL emit buffered output in deterministic order.

#### Scenario: Sequence-based ordering
- **WHEN** buffered lines are flushed
- **THEN** lines are ordered by ingest sequence with stable insertion-index tie-break.

### Requirement: Bounded Ingest and Flush Transparency
The streaming path SHALL enforce line-size and buffer limits with explicit truncation markers.

#### Scenario: Oversized line protection
- **WHEN** a line exceeds the `32 MiB` ingest limit
- **THEN** the runner truncates the stored line and emits an oversized-line truncation marker.

#### Scenario: High-water forced flush marker
- **WHEN** a context exceeds buffered-line high-water limits
- **THEN** output includes an explicit marker that lines were elided.

### Requirement: Masking and Derived-Key Safety
Derived dedupe keys SHALL be generated by ordered baseline masking with boundary-safe numeric rules and bounded horizon.

#### Scenario: Baseline masking order
- **WHEN** derived keys are computed
- **THEN** masks are applied in order: UUID, hex address, numeric noise.

#### Scenario: Numeric boundary rule
- **WHEN** numeric masking is applied
- **THEN** only whole numeric tokens matching `\b[0-9]{10,}\b` are masked.

#### Scenario: Default and override horizon
- **WHEN** filters do not provide a masking horizon
- **THEN** key derivation uses the default 1024-byte prefix.
- **AND WHEN** filters provide a horizon override
- **THEN** the override is used for derived-key masking scope.

### Requirement: Audit Metadata Contract
The engine SHALL emit per-event audit metadata and gate inline debug emission behind `--debug-filter`.

#### Scenario: Per-event audit metadata is attached to engine output
- **WHEN** the engine processes events
- **THEN** output includes structured audit metadata fields (`sequence`, `commandId`, `tool`, `stream`, `action`)
- **AND** verbose audit fields (`raw`, `derivedKey`, `mask`, `collisionBit`) are omitted when audit is disabled.

#### Scenario: Collision bit
- **WHEN** two distinct raw lines resolve to the same derived key within a context/session
- **THEN** the audit record marks `collisionBit=true`.

#### Scenario: Inline debug gating
- **WHEN** `--debug-filter` is not enabled
- **THEN** audit metadata is not injected into stdout/stderr output streams.

### Requirement: CI Validation Gates
The project SHALL validate semantic engine behavior with canonical fixtures and deterministic replay checks.

#### Scenario: Canonical fixture coverage
- **WHEN** CI validation runs
- **THEN** fixture corpus includes noise-bomb, race-condition, deep-json, and collision-sensitive classes.

#### Scenario: Replay determinism
- **WHEN** race-condition fixtures are replayed repeatedly
- **THEN** filtered output is bit-for-bit identical across runs.

#### Scenario: Gate analyzability
- **WHEN** semantic-engine audit records are analyzed in tests/validation gates
- **THEN** records include sufficient metadata (`derivedKey`, `action`, `collisionBit`, context identifiers) for automated gate calculations.
